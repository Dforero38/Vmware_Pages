¿Cómo se Licencia VMware?

El portafolio de VMware opera bajo un modelo de suscripción basado en Cores. Se eliminan las licencias perpetuas y el modelo por socket tradicional.

Regla de Cálculo de Cores

Se requiere cotizar el total de cores físicos del servidor con un mínimo obligatorio de 16 cores por procesador (Socket).

Fórmula básica de cálculo:

Cores por Servidor = Sockets × Máx(Cores Físicos por Socket, 16)

Cores Totales a Licenciar = Servidores × Cores por Servidor

Ingresa la topología de hardware de tu infraestructura para obtener la cantidad exacta de cores a licenciar y el almacenamiento vSAN asignado según el esquema VCF o VVF.

Los 2 Tipos Principales de Licenciamiento

Broadcom consolida la oferta de virtualización de centros de datos en dos soluciones integradas principales:

VVF

VMware vSphere Foundation

Enfoque: Solución de virtualización de cómputo para centros de datos tradicionales que requieren gestión centralizada y operaciones básicas.

  • vSphere Enterprise Plus
  • vCenter Server
  • VCF Operations
  • Derecho a vSAN (0,25 TiB por core suscrito)
VCF

VMware Cloud Foundation

Enfoque: Plataforma completa de Software-Defined Data Center (SDDC) para nube privada e híbrida con automatización avanzada.

  • Todo lo incluido en VVF
  • SDDC Manager (Orquestación LCM)
  • vSAN Enterprise (1 TiB por core suscrito)
  • NSX Enterprise / Advanced Network & Security
  • VCF Operations Suite completa

Arquitectura de Despliegue

VCF organiza la infraestructura mediante la separación clara de planos de control y cargas de negocio:

1. Management Domain

Clúster inicial dedicado exclusivamente a los componentes de administración del SDDC (vCenter, SDDC Manager, clúster de NSX Manager, Aria Operations).

2. VI Workload Domains (Virtual Infrastructure)

Clústeres secundarios dedicados a alojar las aplicaciones finales de negocio, aislados operacionalmente del dominio de gestión.

Sizing y Requisitos Mínimos

Requisitos para Management Domain (VCF)

  • Mínimo de Nodos: 4 hosts ESXi dedicados.
  • RAM por Host: Mínimo 256 GB (512 GB recomendado).
  • Red: Mínimo 2 puertos de 10GbE / 25GbE por host.
  • Almacenamiento: vSAN recomendado para el dominio de gestión.

Criterios de Sizing para Cargas

  • Factor N+1 / N+2: Reservar capacidad de cómputo y memoria suficiente para soportar la caída de 1 o 2 nodos sin degrado.
  • Cálculo de Cores vs vCPU: Relación vCPU:pCore común entre 3:1 y 5:1 según el perfil de la carga.
  • vSAN Slack Space: Mantener un 10-20% de espacio libre reservado para tareas de balanceo y reconstrucción.
